# cafe-provans
Сайт для ресторану Provans який знаходиться в місті Болехів із AI офіціантом


## Backend

**Запуск:** `cp .env.example .env`, підставити пароль БД, далі `docker compose up --build`.
API: `/api/v1/...`, перевірка стану: `/health`, документація: `/docs` (вимкнена в production).

**Тести** (потрібна піднята БД; створюється окрема база `<DB_NAME>_test`, робочу вони не чіпають):

```
docker compose exec backend pip install -r requirements-dev.txt
docker compose exec backend pytest
```

**Як влаштований модуль** (еталон: `backend/app/modules/categories`):

| Файл | За що відповідає |
|---|---|
| `schemas.py` | що приймаємо й віддаємо: `Create` / `Update` / `Read` |
| `service.py` | уся бізнес-логіка та транзакція: метод, що пише, сам викликає `commit()`; кидає `NotFoundError`, `ConflictError` тощо, про HTTP не знає |
| `router.py` | лише HTTP: розбір запиту, права (`require_roles`), виклик сервісу |

Новий модуль: скопіювати `categories`, замінити модель і підключити роутер у `backend/app/api/router.py`.

**Помилки** завжди в одному форматі: `{"error": {"code", "message", "details", "request_id"}}`. `code` для фронтенду, `message` для людини, `request_id` збігається із заголовком `X-Request-ID` і рядком у логах.

**Права:** `Depends(require_roles(UserRole.waiter))`, адмін проходить скрізь. Без входу захищені ендпоінти відповідають 401, з токеном іншої ролі 403. Як працює вхід, див. розділ нижче.

### Вхід персоналу (логін + пароль, JWT)

**Налаштування** (додати у `.env`, його читає `docker-compose`):

```
# Обов'язково, щонайменше 32 символи. Згенерувати: python -c "import secrets; print(secrets.token_urlsafe(48))"
# Зміна ключа розлогінює всіх. Без нього backend не стартує.
JWT_SECRET=...

# Необов'язково (значення за замовчуванням)
ACCESS_TOKEN_TTL_MINUTES=30
REFRESH_TOKEN_TTL_DAYS=14

# Куди надсилати код «забув пароль»: log (код лише в логах backend, для розробки) або smtp (лист на email адміна).
# У production дозволено лише smtp.
OTP_SENDER=log
# SMTP_HOST=smtp.example.com
# SMTP_PORT=587
# SMTP_SECURITY=starttls        # starttls (587) | ssl (465) | none
# SMTP_USER=...
# SMTP_PASSWORD=...
# SMTP_FROM=Provans <no-reply@example.com>
```

Після оновлення коду: `docker compose up --build` (нова бібліотека PyJWT; міграція `0004` застосовується при старті контейнера).

**Перший адміністратор** створюється командою (пароль запитується в терміналі, його не видно і він не потрапляє в історію):

```
docker compose exec backend python -m app.db.create_admin --login admin --full-name "Іван Петренко" --email admin@example.com
docker compose exec backend python -m app.db.create_admin --login admin --reset-password   # аварійно, якщо немає доступу до email
```

Усіх інших працівників створює адміністратор через `POST /api/v1/users`.

| Запит | Що робить |
|---|---|
| `POST /auth/login` `{login, password}` | пара токенів + дані користувача. Логін регістронезалежний |
| `POST /auth/refresh` `{refresh_token}` | нова пара токенів; старий refresh-токен перестає діяти |
| `POST /auth/logout` `{refresh_token}` | завершує цей вхід (інші пристрої лишаються). Завжди 204 |
| `GET /auth/me` | хто я |
| `POST /auth/change-password` `{current_password, new_password}` | міняє свій пароль, завершує всі інші входи, повертає нову пару токенів |
| `POST /auth/forgot-password` `{login}` | **лише для адміністратора.** Завжди 202 з однаковою відповіддю (за нею не вгадати, чи є такий акаунт); код надсилається, якщо акаунт активний, це адмін і в нього є email |
| `POST /auth/reset-password` `{login, code, new_password}` | новий пароль за кодом з листа; знімає блокування |
| `GET/POST /users`, `GET/PATCH /users/{id}` | (admin) список із фільтрами `role`, `is_active`, `location_id`; створення; зміна. Працівників не видаляють, а вимикають (`is_active: false`) |
| `POST /users/{id}/reset-password` | (admin) скидає пароль працівника: повертає **тимчасовий пароль один раз** (старий побачити неможливо), працівник мусить замінити його при першому вході |

Токени передаються заголовком `Authorization: Bearer <access_token>`. У `/docs` кнопка **Authorize** приймає саме `access_token`.

**Як це працює:**

- **Access-токен** (JWT, 30 хв) несе лише id користувача й номер «покоління» токенів. Роль, `is_active` і все інше береться з БД на кожен запит: вимкнений працівник або змінена роль діють одразу, а не через 30 хвилин.
- **Refresh-токен** (14 днів) це випадковий рядок; у БД лежить лише його хеш. Кожне оновлення видає новий і відкликає старий. Якщо відкликаний токен прийшов вдруге (його вкрали або використали двічі), відкликається весь ланцюжок і вхід доведеться повторити. Два одночасні `refresh` з одним токеном (дві вкладки) це теж «повторне використання»: фронтенд має оновлювати токен в одному місці.
- Зміна пароля, скидання пароля й вимкнення працівника збільшують його «покоління»: усі раніше видані access-токени одразу перестають діяти, а refresh-токени відкликаються. Звичайний `logout` access-токен не відкликає: він діє до кінця свого короткого терміну.
- **Тимчасовий пароль.** Доки працівник його не замінив, будь-який запит, окрім `/auth/me`, `/auth/change-password`, `/auth/logout`, дає 403 `password_change_required`. Прапорець `must_change_password` є у відповіді входу.
- **Захист від підбору:** 5 невдалих входів поспіль блокують акаунт на 15 хвилин (429 `account_locked`, `Retry-After`, `details.retry_after_seconds`). Під час блокування навіть правильний пароль не приймається. Невдала спроба в `change-password` рахується так само. Зняти блокування можна скиданням пароля. Блокування за IP робиться на рівні nginx.
- **Код відновлення:** 6 цифр, діє 10 хвилин, 5 спроб, не більше 3 запитів на годину; діє лише найновіший код. Сам код у БД не зберігається (лише HMAC).
- Не можна вимкнути або позбавити ролі останнього активного адміністратора (409 `last_admin`) і скинути пароль самому собі через `/users/{id}/reset-password` (для себе: `change-password` або «забув пароль»).

**Коди помилок для фронтенду:** `not_authenticated` / `invalid_token` (потрібен вхід), `token_expired` (спробувати `refresh`), `invalid_credentials`, `account_locked`, `account_disabled`, `password_change_required`, `invalid_refresh_token` (розлогінити), `invalid_otp`, `invalid_current_password`, `same_password`.

### Меню: керування стравами, закладами і фото (адмін)

Категорії меню керуються через `/categories` (вже було). Страви, заклади й фото:

| Запит | Хто | Що робить |
|---|---|---|
| `GET /dishes` | admin | усі страви, навіть ті, що ніде не продаються. Фільтри `category_id`, `location_id`, `is_available`, сторінки `limit`/`offset` |
| `POST /dishes` | admin | створити страву: категорія, назва, ціна, опис, вага, `allergen_ids`, `locations` |
| `GET/PATCH/DELETE /dishes/{id}` | admin | одна страва; зміна лише переданих полів (`allergen_ids` замінює весь набір); видалення |
| `PUT /dishes/{id}/locations/{location_id}` | admin | додати страву в заклад або змінити її там: `is_available`, `price_override` (власна ціна закладу; без неї діє базова) |
| `DELETE /dishes/{id}/locations/{location_id}` | admin | прибрати страву з меню закладу |
| `PATCH /locations/{id}/menu/{dish_id}/availability` `{is_available}` | waiter, admin | **стоп-лист**: страва закінчилась / знову є. Офіціант лише у своєму закладі (`users.location_id`), адмін у будь-якому |
| `POST /dishes/{id}/image`, `DELETE /dishes/{id}/image` | admin | фото страви |
| `GET/POST /admin/locations`, `GET/PATCH /admin/locations/{id}` | admin | усі заклади (і неактивні); створення (одразу з зеленою/жовтою/червоною зонами доставки); зміна. Заклад не видаляється, а вимикається `is_active: false` |
| `POST /admin/locations/{id}/image`, `DELETE ...` | admin | фото закладу |

Як це влаштовано:

- Страва, створена без `locations`, з'являється **в усіх наявних закладах**. Щоб додати лише в деякі, передайте `locations: [{"location_id": 1, "price_override": 200}]`, а `locations: []` означає «поки ніде».
- Двох рівнів «доступності» два: `dishes.is_available` (адмін знімає страву з продажу всюди) і `dish_locations.is_available` (стоп-лист конкретного закладу, його міняє офіціант). У меню гостя страва доступна, лише якщо увімкнені обидва.
- Страву, що є в замовленнях чи акціях, видалити не можна (409 `dish_in_use`): зніміть її з продажу або приберіть із закладів. Історія замовлень лишається цілою.
- Ціна в гривнях, до двох знаків після коми, не більше 100 000.

**Фото.** Зберігаються на диску того ж сервера, де працює код: у папці `backend/media/` (`dishes/`, `locations/`). У БД лежить лише адреса виду `/media/dishes/dish-7-3fa9c2d41b0e8a55.jpg`, відкривається вона без входу.

- Формати: JPEG, PNG, WebP, до 5 МБ. Тип визначається за вмістом файлу, а не за назвою; SVG і будь-що інше відхиляється (422 `unsupported_image`, `image_too_large`). Ім'я файлу генерує сервер, назва від користувача на диск не потрапляє.
- Нове фото замінює старе (старий файл видаляється), видалення страви видаляє її фото. Папка `backend/media/` у `.gitignore`, **її треба включати в резервні копії разом із БД**, бо в git фото не лежать.
- Папка підключена в контейнер разом із кодом (`./backend:/app`), тож фото переживають перезбірку образу. Інше місце можна задати змінною `MEDIA_DIR`.
- `nginx/conf.d/default.conf` має `client_max_body_size 6m`, інакше nginx відхиляв би файли понад 1 МБ ще до backend.
- Фронтенд має брати адреси `/media/...` з того ж домену, що й `/api`: якщо фронтенд віддається окремим nginx, там треба проксіювати `/media/` на backend так само, як `/api/`.

### Публічне API для сайту (без входу)

Після оновлення коду один раз застосувати міграцію: `docker compose exec backend alembic upgrade head`.

| Запит | Що віддає |
|---|---|
| `GET /api/v1/locations`, `GET /api/v1/locations/{id}` | активні заклади; `is_open_now` рахується за місцевим часом закладу (`null`, якщо години не задані) |
| `GET /api/v1/locations/{id}/menu` | меню закладу по категоріях, ціна з урахуванням власної ціни закладу; `?available_only=true` ховає стоп-лист, `?featured=true` лише страви для головної |
| `GET /api/v1/locations/{id}/promotions` | акції, що діють просто зараз (статус, дата й час за часом закладу, пауза, якщо страви немає); `?featured=true` |
| `GET /api/v1/locations/{id}/delivery` | зони доставки, мінімальні суми (доставка безкоштовна), `areas` (які міста й вулиці входять у кожну зону) і `map_url` (карта зон для показу на сайті) |
| `POST /api/v1/locations/{id}/delivery/check-address` | **основний спосіб.** Тіло `{"city": "Болехів", "street": "вул. Шевченка"}` (`street` необов'язкова). Відповідь: зона й мінімум, або `deliverable: false` із причиною: `outside_zones` (лише самовивіз), `street_required` (місто задано переліком вулиць, треба вулицю), `ambiguous_street` (вулиця без типу є і як «вул.», і як «пров.» у різних зонах), `not_configured` (для закладу ще не внесено зон) |
| `POST /api/v1/locations/{id}/delivery/check` | запасний спосіб за координатами `{"lat": 49.05, "lng": 23.85}` за контурами на карті (потрібен імпорт KML, див. нижче) |
| `GET /api/v1/allergens` | довідник алергенів |

Неактивний або неіснуючий заклад завжди дає 404. Суми в JSON це звичайні числа (`180.0`). Перевірка адреси це POST навмисно: координати гостя не повинні потрапляти в адресу запиту, а отже в логи проксі.

### Зони доставки: хто в якій зоні

Усі заклади мережі називаються однаково (Provans) і різняться містом та адресою (`locations.city`, `locations.address`). Кожен заклад має свої зони (зелена, жовта, червона зі стандартними мінімумами 400 / 600 / 1000 грн; їх створює `seed`, а для нового закладу `seed_delivery_zones(session, location_id)`).

Яка адреса в якій зоні, вносить адміністратор вручну в таблицю `delivery_zone_areas`:

- **ціле місто в зоні:** запис з `street = ''` (місто, жодна вулиця не потрібна);
- **лише частина міста:** окремий запис на кожну вулицю зони;
- **вулиця переважає над містом:** якщо місто в жовтій зоні, а «вул. Шевченка» в зеленій, то Шевченка зелена, решта міста жовта;
- чого немає в жодній зоні, те лише самовивіз.

Порівняння не чутливе до регістру, апострофа (`'`, `ʼ`, `’` чи без нього), «м.», «с.», «вул.», «вулиця», номера будинку. «вул. Шевченка» і «пров. Шевченка» вважаються різними вулицями. Гостю на сайті краще давати вибір міста й вулиці зі списку `areas` із `GET /delivery`, тоді помилок у написанні не буде.

Поки немає адмін-панелі, вносити можна SQL-ом (приклад для закладу з `id = 1`):

```sql
UPDATE locations SET city = 'Болехів',
  delivery_map_url = 'https://www.google.com/maps/d/embed?mid=18hNmLUbGNEeWuByxKwuwh4IIhX7Xh8M'
WHERE id = 1;

-- ціле місто в жовтій зоні
INSERT INTO delivery_zone_areas (location_id, zone_id, city, street)
SELECT 1, id, 'Болехів', '' FROM delivery_zones WHERE location_id = 1 AND code = 'yellow';

-- а вулиця Шевченка в зеленій
INSERT INTO delivery_zone_areas (location_id, zone_id, city, street)
SELECT 1, id, 'Болехів', 'вул. Шевченка' FROM delivery_zones WHERE location_id = 1 AND code = 'green';
```

`delivery_map_url` це що вбудовується на сайті (`<iframe src=...>`), приймається лише `https://`. Це може бути посилання вбудовування Google My Maps.

### Контури зон з Google My Maps (необов'язково)

Для перевірки за адресою контури не потрібні. Але якщо вони є, їх можна завантажити в БД (`delivery_zones.polygon`, GeoJSON) із карти, яку вже намальовано: це вмикає запасну перевірку за координатами й дозволяє малювати карту зон самостійно, а не через вбудовування.

1. На карті: `⋮` біля назви, «Експортувати в KML/KMZ», обрати шар(и) із зонами, формат KML.
2. Покласти файл у `backend/` (його має бачити контейнер) і спершу зробити пробний запуск:
   ```
   docker compose exec backend python -m app.db.import_zones --location-id 1 zones_bolekhiv.kml --dry-run
   ```
3. Якщо звіт правильний, той самий запуск без `--dry-run`.

Кожна карта це один заклад, тож для двох закладів імпорт запускається двічі з різними `--location-id` (заклад має існувати в БД). Зону багатокутника визначено за назвою («Зелена зона», «Жовта», «Red»), інакше за назвою шару, інакше за кольором заливки. Якщо нічого не підійшло, імпорт скаже, який багатокутник не впізнано; тоді назвіть його на карті або вкажіть вручну: `--assign "Центр=green"` (`green`, `yellow`, `red`). Повторний запуск просто замінює контури; назви й мінімальні суми зон імпорт не чіпає, а відсутні зони створює зі стандартними (400 / 600 / 1000 грн). Помилка в будь-якому багатокутнику скасовує весь імпорт.
