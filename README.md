# cafe-provans
Сайт для ресторану Provans який знаходиться в місті Болехів із AI офіціантом


## Backend

**Запуск:** `cp .env.example .env`, підставити пароль БД, далі `docker compose up --build`.
API: `/api/v1/...`, перевірка стану: `/health`, документація: `/docs` (вимкнена в production).

**Тести** (потрібна піднята БД; створюється окрема база `<DB_NAME>_test`, робочу вони не чіпають):

```
docker compose exec backend pip install -r requirements-dev.txt
docker compose exec backend pytest
```

**Як влаштований модуль** (еталон: `backend/app/modules/categories`):

| Файл | За що відповідає |
|---|---|
| `schemas.py` | що приймаємо й віддаємо: `Create` / `Update` / `Read` |
| `service.py` | уся бізнес-логіка та транзакція: метод, що пише, сам викликає `commit()`; кидає `NotFoundError`, `ConflictError` тощо, про HTTP не знає |
| `router.py` | лише HTTP: розбір запиту, права (`require_roles`), виклик сервісу |

Новий модуль: скопіювати `categories`, замінити модель і підключити роутер у `backend/app/api/router.py`.

**Помилки** завжди в одному форматі: `{"error": {"code", "message", "details", "request_id"}}`. `code` для фронтенду, `message` для людини, `request_id` збігається із заголовком `X-Request-ID` і рядком у логах.

**Права:** `Depends(require_roles(UserRole.waiter))`, адмін проходить скрізь. Доки не реалізований вхід, захищені ендпоінти відповідають 401.

### Публічне API для сайту (без входу)

Після оновлення коду один раз застосувати міграцію: `docker compose exec backend alembic upgrade head`.

| Запит | Що віддає |
|---|---|
| `GET /api/v1/locations`, `GET /api/v1/locations/{id}` | активні заклади; `is_open_now` рахується за місцевим часом закладу (`null`, якщо години не задані) |
| `GET /api/v1/locations/{id}/menu` | меню закладу по категоріях, ціна з урахуванням власної ціни закладу; `?available_only=true` ховає стоп-лист, `?featured=true` лише страви для головної |
| `GET /api/v1/locations/{id}/promotions` | акції, що діють просто зараз (статус, дата й час за часом закладу, пауза, якщо страви немає); `?featured=true` |
| `GET /api/v1/locations/{id}/delivery` | зони доставки, мінімальні суми (доставка безкоштовна), `areas` (які міста й вулиці входять у кожну зону) і `map_url` (карта зон для показу на сайті) |
| `POST /api/v1/locations/{id}/delivery/check-address` | **основний спосіб.** Тіло `{"city": "Болехів", "street": "вул. Шевченка"}` (`street` необов'язкова). Відповідь: зона й мінімум, або `deliverable: false` із причиною: `outside_zones` (лише самовивіз), `street_required` (місто задано переліком вулиць, треба вулицю), `ambiguous_street` (вулиця без типу є і як «вул.», і як «пров.» у різних зонах), `not_configured` (для закладу ще не внесено зон) |
| `POST /api/v1/locations/{id}/delivery/check` | запасний спосіб за координатами `{"lat": 49.05, "lng": 23.85}` за контурами на карті (потрібен імпорт KML, див. нижче) |
| `GET /api/v1/allergens` | довідник алергенів |

Неактивний або неіснуючий заклад завжди дає 404. Суми в JSON це звичайні числа (`180.0`). Перевірка адреси це POST навмисно: координати гостя не повинні потрапляти в адресу запиту, а отже в логи проксі.

### Зони доставки: хто в якій зоні

Усі заклади мережі називаються однаково (Provans) і різняться містом та адресою (`locations.city`, `locations.address`). Кожен заклад має свої зони (зелена, жовта, червона зі стандартними мінімумами 400 / 600 / 1000 грн; їх створює `seed`, а для нового закладу `seed_delivery_zones(session, location_id)`).

Яка адреса в якій зоні, вносить адміністратор вручну в таблицю `delivery_zone_areas`:

- **ціле місто в зоні:** запис з `street = ''` (місто, жодна вулиця не потрібна);
- **лише частина міста:** окремий запис на кожну вулицю зони;
- **вулиця переважає над містом:** якщо місто в жовтій зоні, а «вул. Шевченка» в зеленій, то Шевченка зелена, решта міста жовта;
- чого немає в жодній зоні, те лише самовивіз.

Порівняння не чутливе до регістру, апострофа (`'`, `ʼ`, `’` чи без нього), «м.», «с.», «вул.», «вулиця», номера будинку. «вул. Шевченка» і «пров. Шевченка» вважаються різними вулицями. Гостю на сайті краще давати вибір міста й вулиці зі списку `areas` із `GET /delivery`, тоді помилок у написанні не буде.

Поки немає адмін-панелі, вносити можна SQL-ом (приклад для закладу з `id = 1`):

```sql
UPDATE locations SET city = 'Болехів',
  delivery_map_url = 'https://www.google.com/maps/d/embed?mid=18hNmLUbGNEeWuByxKwuwh4IIhX7Xh8M'
WHERE id = 1;

-- ціле місто в жовтій зоні
INSERT INTO delivery_zone_areas (location_id, zone_id, city, street)
SELECT 1, id, 'Болехів', '' FROM delivery_zones WHERE location_id = 1 AND code = 'yellow';

-- а вулиця Шевченка в зеленій
INSERT INTO delivery_zone_areas (location_id, zone_id, city, street)
SELECT 1, id, 'Болехів', 'вул. Шевченка' FROM delivery_zones WHERE location_id = 1 AND code = 'green';
```

`delivery_map_url` це що вбудовується на сайті (`<iframe src=...>`), приймається лише `https://`. Це може бути посилання вбудовування Google My Maps.

### Контури зон з Google My Maps (необов'язково)

Для перевірки за адресою контури не потрібні. Але якщо вони є, їх можна завантажити в БД (`delivery_zones.polygon`, GeoJSON) із карти, яку вже намальовано: це вмикає запасну перевірку за координатами й дозволяє малювати карту зон самостійно, а не через вбудовування.

1. На карті: `⋮` біля назви, «Експортувати в KML/KMZ», обрати шар(и) із зонами, формат KML.
2. Покласти файл у `backend/` (його має бачити контейнер) і спершу зробити пробний запуск:
   ```
   docker compose exec backend python -m app.db.import_zones --location-id 1 zones_bolekhiv.kml --dry-run
   ```
3. Якщо звіт правильний, той самий запуск без `--dry-run`.

Кожна карта це один заклад, тож для двох закладів імпорт запускається двічі з різними `--location-id` (заклад має існувати в БД). Зону багатокутника визначено за назвою («Зелена зона», «Жовта», «Red»), інакше за назвою шару, інакше за кольором заливки. Якщо нічого не підійшло, імпорт скаже, який багатокутник не впізнано; тоді назвіть його на карті або вкажіть вручну: `--assign "Центр=green"` (`green`, `yellow`, `red`). Повторний запуск просто замінює контури; назви й мінімальні суми зон імпорт не чіпає, а відсутні зони створює зі стандартними (400 / 600 / 1000 грн). Помилка в будь-якому багатокутнику скасовує весь імпорт.
